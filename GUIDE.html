A folder you can keep

For a new archive, open __email_archiver/index.html locally to read and search. Older archives may have index.html at the root. No server, login or internet connection is required.

Import your first MBOX

  1. Use desktop Chrome or Edge and click the green Import button and use the Import MBOX section.
  2. Enter an account folder name, such as personal. This is a subfolder name, not a disk path.
  3. Choose the archive root folder: the parent folder containing __email_archiver/ and your account folders, or a new empty folder. Do not pick the application subfolder. The application will be copied there. For private mail, choose a folder outside the public project checkout.
  4. Select MBOX files, check free disk space, then start. Thunderbird files do not need an extension; unpack Takeout ZIPs first.
  5. When finished, open __email_archiver/index.html inside a new archive (or the root index.html of an older archive).

Choosing root MyMail and account personal stores the viewer at MyMail/__email_archiver/index.html and mail in MyMail/personal/…. Old archive layouts are preserved rather than moved automatically.

Image loading and return position

Browse archive shows a small Load external images automatically checkbox, checked by default. Newly generated HTML message pages opened from the archive honor that setting: when checked, external images load and may reveal your IP address or message tracking token to senders. Uncheck it to keep external images blocked and use each email's Load button instead. Direct standalone HTML files without the viewer preference remain blocked by default. The preference is session-scoped when browser storage is available.

New message pages use browser history when their Back to archive link is clicked, restoring the previous position. The archive also tries to remember the search filters, page and scroll position in tab-scoped session storage for older saved pages. These optional behaviors do not modify message contents. To add new script controls to older HTML emails, the pages must be regenerated from the original MBOX or updated separately.

Import and repair on the same page

Use the green Import button at the upper right. This switches sections inside the same index.html; Browse archive returns to the viewer. Import MBOX and Repair catalog share one Import folder root selection, but remain visually separate. The import account is used only when importing.

The last selected folder and account name are automatically preselected when browser storage allows it. Click Import folder root to pick a different archive. A remembered directory handle alone does not grant file permission; Chrome may prompt when you start importing or preview a repair. The selected root appears below the button as a folder-relative path and, when accessible, the index path and indexed count. Chrome does not expose an absolute path for a folder selected through this API.

Repair uses exactly the selected root, and requires a new preview after changing folders. It does not change the archive shown in Browse, which always reads the index.html opened in the current browser tab. Selecting a different target does not make the Browse links unclickable.

Update older saved email reader controls without MBOX

If the Browse checkbox says Load external images automatically but your previously saved HTML messages still show a manual Load button, those pages were generated with the older standalone reader. Choose the correct archive root under Import and find Update saved email reader controls beneath catalog repair. Preview eligible pages, back up the complete archive, then click Update saved readers. This upgrades only an authenticated old reader script and Content Security Policy, preserving decoded message content, embedded metadata, attachments, originals and search indexes. Unrecognized HTML is skipped. Importing the original MBOX and rebuilding the search catalog are unnecessary.

Restore original email appearance

For an existing archive, back up the complete folder. Choose the same archive root and account, select your original MBOX files, and tick Rebuild the appearance of existing messages. Existing message HTML is regenerated with safer colors, fonts, and common HTML layout rules. Duplicate messages or attachments are not added. If you no longer have the original MBOX, the formatting discarded by the old importer cannot be recovered from the stripped HTML pages.

Embedded CID images work offline. External images remain blocked unless the archive viewer explicitly opens a compatible saved page with automatic loading enabled, or you click Load external images manually. This requires internet access and can reveal your IP address or tracking token to the image host. Active content remains blocked; complex HTML may still differ from Thunderbird.

Repair or rebuild the catalog without MBOX

Open the Repair catalog tab in Chrome or Edge, choose your archive root, then preview the scan. After backing up the whole archive, run Rebuild search catalog. The program scans account/year/month directories for saved email-*.html pages and recreates search indexes without changing those email pages or attachments. Older HTML pages may have incomplete metadata; signatures and original MIME data are not recovered. Never run this during an import.

Next export or interrupted import

Select the same root and account. Known messages are skipped, Gmail labels are merged, and earlier mail is retained. Stop finishes the current message and commits the batch. After a crash, reimport from the beginning. Keep the tab open and use only one writer, including across synced devices.

Copy, cloud backup and another computer

Copy the entire parent archive folder, including both __email_archiver and all account folders, after stopping or finishing import. Download or mark all cloud files as available offline, then open the local index.html. A cloud website preview is not the application. Reading needs no previous browser profile; future imports require selecting the folder again.

Files you should keep

__email_archiver/assets/catalog/archive.js is the current generated manifest in new archives; __email_archiver/assets/catalog/archive.previous.js points to the previous snapshot. Legacy manifests at assets/catalog/ and the root remain supported. Older root-level manifests are supported for backward compatibility. Both reference catalog files inside account folders. archive.lock in __email_archiver/ (or at the root of older archives) coordinates imports and contains no mail. Source code is in index.html and assets. The easiest safe backup is the whole folder.

Manually copying arbitrary HTML or EML into an account folder does not automatically register it in the catalog. Use the importer to make messages visible in the main index.

Safety and fidelity

DOMPurify and strict allow-lists remove scripts, event handlers, forms, frames, dangerous CSS and automatic remote image loading. Safe colors, fonts and supported layout styles survive. CID raster images use local files. Every message has a restrictive CSP. Links to external websites open only when clicked. Potentially active attachments receive a .download suffix; attachments are not virus-scanned. The archive is not encrypted.

This is a safe readable representation, not a byte-for-byte copy of every original header and MIME part. Keep the original MBOX separately if you need complete source fidelity.

Original email and signatures

New HTML messages carry decoded MIME/header metadata in inert embedded JSON for future catalog repair. This is descriptive metadata, not the original signed bytes. DKIM, S/MIME or PGP cryptographic verification can fail without original MIME content, certificates or keys. Keep the source MBOX for evidentiary fidelity. Catalog rebuilding is not a substitute for retaining original signatures.

Limits

One message may be at most 64 MiB. Large imports can take hours because each message is a separate file. Search uses text indexes and may take seconds on large archives. Dates are grouped in UTC; missing dates use unknown-date. Binary attachments are not text-indexed, encrypted content is not decrypted and embedded-message previews are limited to three levels. Automatic catalog compaction and registration of manually added files are not implemented.

Chrome was tested. Edge is targeted but not independently verified; Firefox/Safari reading and Linux operation were not independently verified for this package.

Optional original EML retention

During MBOX import, keep signed/encrypted messages as original-format EML copies by default. Gmail Starred and Important copies are optional and use additional space. Source EML files are checksummed and linked from the readable HTML; retaining the original MBOX is still recommended for full provenance.
