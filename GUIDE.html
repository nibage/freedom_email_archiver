A folder you can keep

Open index.html locally to read and search the archive. No server, login or internet connection is required.

Import your first MBOX

  1. Use desktop Chrome or Edge and open the Import MBOX tab.
  2. Enter an account folder name, such as personal. This is a subfolder name, not a disk path.
  3. Choose the archive root folder: the folder containing index.html, or a new empty folder. The application will be copied there. For private mail, choose a folder outside the public project checkout.
  4. Select MBOX files, check free disk space, then start. Thunderbird files do not need an extension; unpack Takeout ZIPs first.
  5. When finished, open index.html in the selected archive root.

Choosing root MyMail and account personal stores messages under MyMail/personal/….

Next export or interrupted import

Select the same root and account. Known messages are skipped, Gmail labels are merged, and earlier mail is retained. Stop finishes the current message and commits the batch. After a crash, reimport from the beginning. Keep the tab open and use only one writer, including across synced devices.

Copy, cloud backup and another computer

Copy the entire folder after stopping or finishing import. Download or mark all cloud files as available offline, then open the local index.html. A cloud website preview is not the application. Reading needs no previous browser profile; future imports require selecting the folder again.

Files you should keep

archive.js is the current generated manifest; archive.previous.js points to the previous snapshot. Both reference catalog files inside account folders. archive.lock coordinates local imports and contains no mail. Source code is in index.html and assets. The easiest safe backup is the whole folder.

Manually copying HTML or EML into an account folder does not update the catalog. Use the importer to make messages visible in the main index.

Safety and fidelity

DOMPurify and strict allow-lists remove scripts, event handlers, forms, frames, original styles and remote images. CID raster images use local files. Every message has a restrictive CSP. Links to external websites open only when clicked. Potentially active attachments receive a .download suffix; attachments are not virus-scanned. The archive is not encrypted.

This is a safe readable representation, not a byte-for-byte copy of every original header and MIME part. Keep the original MBOX separately if you need complete source fidelity.

Limits

One message may be at most 64 MiB. Large imports can take hours because each message is a separate file. Search uses text indexes and may take seconds on large archives. Dates are grouped in UTC; missing dates use unknown-date. Binary attachments are not text-indexed, encrypted content is not decrypted and embedded-message previews are limited to three levels. Automatic catalog compaction and registration of manually added files are not implemented.

Chrome was tested. Edge is targeted but not independently verified; Firefox/Safari reading and Linux operation were not independently verified for this package.
