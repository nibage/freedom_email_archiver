A folder you can keep

Open index.html locally to read and search the archive. No server, login or internet connection is required.

Import your first MBOX

  1. Use desktop Chrome or Edge and open the Import MBOX tab.
  2. Enter an account folder name, such as personal. This is a subfolder name, not a disk path.
  3. Choose the archive root folder: the folder containing index.html, or a new empty folder. The application will be copied there. For private mail, choose a folder outside the public project checkout.
  4. Select MBOX files, check free disk space, then start. Thunderbird files do not need an extension; unpack Takeout ZIPs first.
  5. When finished, open index.html in the selected archive root.

Choosing root MyMail and account personal stores messages under MyMail/personal/….

Current-format imports

This experimental version does not perform one-time migrations from older root-manifest archives. For testing, choose a new empty archive root and import the original MBOX. Reimporting into the same current-format archive will deduplicate messages.

Embedded CID images work offline. External images remain blocked until you explicitly click Load external images in a message. This requires internet access and can reveal your IP address or tracking token to the image host. Active content remains blocked; complex HTML may still differ from Thunderbird.

Optional original-format EML copies

On import, EML preservation has three independent options: signed/encrypted messages are checked by default, while Gmail Starred and Important are unchecked by default. The optional label-based copies consume additional space; Gmail marks many messages Important automatically. Turning off a box does not delete existing retained EMLs. DKIM alone does not trigger a copy. Each selected message keeps its normal standalone HTML and also gains an originals/email-<id>.eml companion. The HTML offers a download link and SHA-256 checksum. The file is extracted from MBOX without MIME reserialization; its source envelope is removed and MBOXrd body escaping is reversed. A saved checksum does not verify sender identity or signatures. Reimporting overlapping MBOX files can preserve or repair EML without duplicating mail; old HTML alone cannot recreate EML. Keep source MBOX backups for evidentiary authenticity.

Repair or rebuild the catalog without MBOX

Open the Repair catalog tab in Chrome or Edge, choose your archive root, then preview the scan. After backing up the whole archive, run Rebuild search catalog. The program scans account/year/month directories for saved email-*.html pages and recreates search indexes without changing those email pages, attachments or EML originals. Only HTML generated with valid self-describing metadata by this format is accepted; damaged or older pages cause the rebuild to fail without publishing a partial catalog. Never run this during an import.

Next export or interrupted import

Select the same root and account. Known messages are skipped, Gmail labels are merged, and earlier mail is retained. Stop finishes the current message and commits the batch. After a crash, reimport from the beginning. Keep the tab open and use only one writer, including across synced devices.

Copy, cloud backup and another computer

Copy the entire folder after stopping or finishing import. Download or mark all cloud files as available offline, then open the local index.html. A cloud website preview is not the application. Reading needs no previous browser profile; future imports require selecting the folder again.

Files you should keep

assets/catalog/archive.js is the current generated manifest; assets/catalog/archive.previous.js points to the previous snapshot. Old root-level manifests are not migrated by this experimental version. Use a new empty archive root for testing. Both reference catalog files inside account folders. archive.lock coordinates local imports and contains no mail. Source code is in index.html and assets. The easiest safe backup is the whole folder.

Manually copying HTML or EML into an account folder does not update the catalog. Use the importer to make messages visible in the main index.

Safety and fidelity

DOMPurify and strict allow-lists remove scripts, event handlers, forms, frames, dangerous CSS and automatic remote image loading. Safe colors, fonts and supported layout styles survive. CID raster images use local files. Every message has a restrictive CSP. Links to external websites open only when clicked. Potentially active attachments receive a .download suffix; attachments are not virus-scanned. The archive is not encrypted.

This is a safe readable representation, not a byte-for-byte copy of every original header and MIME part. Keep the original MBOX separately if you need complete source fidelity.

Original email and signatures

New HTML messages carry decoded MIME/header metadata in inert embedded JSON for future catalog repair. This is descriptive metadata, not the original signed bytes. DKIM, S/MIME or PGP cryptographic verification can fail without original MIME content, certificates or keys. Keep the source MBOX for evidentiary fidelity. Catalog rebuilding is not a substitute for retaining original signatures.

Limits

One message may be at most 64 MiB. Large imports can take hours because each message is a separate file. Search uses text indexes and may take seconds on large archives. Dates are grouped in UTC; missing dates use unknown-date. Binary attachments are not text-indexed, encrypted content is not decrypted and embedded-message previews are limited to three levels. Automatic catalog compaction and registration of manually added files are not implemented.

Chrome was tested. Edge is targeted but not independently verified; Firefox/Safari reading and Linux operation were not independently verified for this package.
